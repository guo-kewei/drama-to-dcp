# 短剧转电影自动化平台 — 整体设计方案 v1.2

> 目标：将短剧公司提供的**宽屏短剧**（多集）批量、全自动转制为影院可放映的 **DCP**；
> 并为走电影备案流程的影片提供**合规材料自动化工作台**（精品化路线，10-30 部/年）。
> 画质"够用即可"，核心是**傻瓜化操作 + 流水线自动批量产出 + 材料环节从 2-4 周压到 1-2 天**。

## 0. 战略定位（2026-11 调研结论）

- "海量短剧×龙标×商业院线"模式不成立：龙标是所有放映路径（院线/艺联/点播影院/农村公益）的唯一闸门，单部 3-5 个月人工审查，现实量级 10-30 部/年
- 转换管线的真实价值：精品化路线的材料+DCP 环节自动化 + 独立电影人免费工具
- 本平台定位 = **转换管线（已建成）+ 备案合规工作台（v1.2 新增）**；不做、也不能做审查替代

## 1. 总体架构（四层，全部开源免费）

```
┌──────────────────────────────────────────────┐
│ UI 层    PySide6 桌面程序（可打包 exe 双击即用） │
│          新建任务向导 │ 任务队列 │ 设置 │ 日志    │
├──────────────────────────────────────────────┤
│ 编排层   app/core（任务模型、状态机、断点恢复）   │
├──────────────────────────────────────────────┤
│ 处理层   app/pipeline（五阶段）                 │
│   视频: probe→normalize→concat(预留enhance)    │
│   音频: 预处理→【上混引擎(可插拔)】→Nch WAV     │
│   封装: dcp → verify 质检                      │
├──────────────────────────────────────────────┤
│ 工具层   FFmpeg │ DCP-o-matic 2.18（GPL 免费） │
└──────────────────────────────────────────────┘
```

## 2. 处理流水线（单任务状态机：扫描分析合并为一个阶段）

`扫描分析 → 归一化(每集) → 拼接 → DCP封装 → 质检 → 完成/失败隔离`

| 阶段 | 实现 | 说明 |
|---|---|---|
| 扫描分析 | `pipeline/probe.py` + `runner._run_scan` | 枚举文件夹视频（自然排序=集序），ffprobe 逐集探测；按源画幅自动推荐容器：宽高比 ≥2.15→Scope(2048×858)，其余→Flat(1998×1080)；Full(2048×1080) 仅手动选 |
| 归一化 | `pipeline/normalize.py` | 每集一条 FFmpeg 命令：视频 `fps=24 + scale(lanczos)/crop 或 pad` → H.264 CRF12 近无损中间件；音频 loudnorm 两遍法(EBU R128) → 48k/24bit；无音轨集生成目标布局静音兜底；归一化前有超分引擎挂载点 |
| 上混 | `engines/`（可插拔） | 规则引擎(默认)：pan 滤镜，对白锚定中置 C=0.5L+0.5R，环绕低电平；支持 5.1(6ch)/7.1(8ch)；AI 引擎预留（命令模板接口，未配置时任务启动即报错而非逐集失败） |
| 拼接 | `pipeline/concat.py` | 视频/音频均 concat demuxer 流复制（list 文件条目绝对路径；音频输出 RF64 防 4GB 溢出，集数不限）+ 可选集间黑场/静音（默认 0.5s） |
| 封装 | `pipeline/dcp.py` | `dcpomatic2_create --container-ratio 185/239/190 --twok|fourk --standard SMPTE -c FTR --no-encrypt`（视频 MP4 + Nch WAV 两内容文件）→ `dcpomatic2_cli` 编码（解析百分比进度）；同名目标追加时间戳不覆盖 |
| 质检 | `pipeline/verify.py` | 结构完整（ASSETMAP/VOLINDEX/CPL/PKL/视频+音频MXF）+ CPL 校验（画幅按任务容器×分辨率、24fps、时长±2s——跳集后按实际参与集重算预期）；失败→隔离区并在错误信息与报告中注明位置 |

## 3. 关键决策记录

- **画幅**：源为宽屏短剧（16:9 或 2.35:1），自动匹配 Flat/Scope；Full 仅手动（影院端需预设，兼容性自负）。
- **帧率**：统一 24fps（30fps 直接抽帧，不做插帧——批量模式接受运动妥协）。
- **音频**：
  - v1 规则上混（FFmpeg pan），对白中置；
  - 架构预留 AI 上混引擎接口（`engines/ai.py`，外部命令模板 `{input} {output} {layout} {channels}`），未来接入 AI 生成 5.1/7.1/沉浸声（DCP 上限 16 声道）；
  - 立体声目标 = 6ch DCP 仅填 L/R（服务器兼容性最好）；
  - 多声道源(≥6ch) 直通重排，不响度归一。
- **加密**：不加密（KDM 分发会摧毁批量模式）。
- **pykdm**：不采用（0.1.0 单版本不成熟），直接调 DCP-o-matic 原生 CLI。
- **视频超分**：v1 不做，`engines/enhance.py` 预留接口。

## 4. 目录结构

```
app/
├── cli.py            # 命令行入口（doctor/probe/convert）
├── main.py           # GUI 入口（M2）
├── core/             # config.py 设置持久化 / task.py 任务模型+状态机
├── pipeline/         # probe/normalize/concat/dcp/verify/runner
├── engines/          # base(注册机制) rule(规则上混) ai(预留) enhance(超分预留)
└── tools/            # ffmpeg.py / dcpomatic.py 外部工具封装
tools/                # 便携版 FFmpeg 等
tests/                # test_units.py 单测 / make_test_media.py 合成测试视频
run.py                # 启动入口
config.json           # 运行时配置（自动生成）
```

运行时输出：`<输出根>/工作区/<任务ID>/`（中间件+state.json）、`DCP/`、`隔离区/`、`reports/`。

## 9. 真实短剧实测记录（万万没想到 S1，2026-11-14）

素材：B 站官方可看资源 yt-dlp 下载 8 集（1920×1080/**25fps**/立体声，共 81.5 分钟正片时长，438MB）。仅作系统测试用，商用需用短剧公司授权素材。

真实素材暴露并已修复的两个问题：
1. **7.1 名称错误**：DCP-o-matic 对 8 声道 DCP 的 ISDCF 名称默认标 `51-HI-VI`（把第 7/8 声道当助听/视障轨）。修复：建工程后改写 film XML 的 Mapping 增益矩阵为逐声道直连（input i→output i，后环绕落 BsL/BsR），并用 `--no-use-isdcf-name` 由平台按 DCNC 规范自拼全名（与界面预览同一函数、完全一致）。实测：`FIX71B_FTR-1_S_XX-XX_71_2K_20261114_SMPTE_OV` ✅
2. **画幅代码**：DCP-o-matic 实际输出 Flat→`F`、Scope→`S`（非文档常写的 C-185/S-239），界面预览已对齐。

其他实测数据：25fps→24fps 转换正常；81.5 分钟片全流程吞吐约 1.2× 实时（归一化 ~10min + J2K 编码 ~100min@150Mbps，2K Flat 成品约 96GB 含音频）。
